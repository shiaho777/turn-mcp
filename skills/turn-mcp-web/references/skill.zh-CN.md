# turn-mcp-web 技能

你有 `turn.wait` 工具，别名是 `turn_wait` 和 `turn`。用它把人工确认保留在同一次 Agent 运行里，而不是结束本轮后重新开新对话。

## 先确认工具存在

开始前先检查当前环境里是否真的有 `turn.wait`、`turn_wait` 或 `turn`。

如果都没有，明确说明这一点，不要假装会话回路已经接通。

## 什么情况下必须调用

当你遇到下面这些节点时，调用 `turn.wait`：

- 做高影响操作前需要人工批准
- 缺少关键信息，下一步无法继续
- 存在明确分支，需要人工选一个方向
- 完成一段阶段性工作后，需要把结果交给人工决定下一步

如果你希望人工回复仍然回到同一次运行里，就不要直接在普通聊天里结束回复，而要走 `turn.wait`。

## 调用格式

```python
turn.wait(
  context="你已经做了什么、发现了什么、接下来会做什么。",
  question="你需要人工回答的那一个具体问题。",
  options=["继续", "修改", "停止"],
  agentName="ReleaseAgent"
)
```

- `context` 必填，而且要写给没看过上下文的人。
- 工具返回的是操作者的原话。会话断开或服务关闭时，结果是 `[interrupted]`。
- `question` 只问一件具体的事。
- `options` 适合已知分支，用按钮代替人工打字。
- `agentName` 在同一条工作流里保持稳定。

## 写法要求

每一条 wait 消息都应该让人工冷启动读懂现场：

- 先概括你已经完成的工作
- 再说明当前卡点或待决策项
- 再说明对方一旦回复，你下一步会做什么

## 保持循环

按这个循环工作：

1. 先做事，直到出现需要人工介入的节点
2. 调用 `turn.wait`
3. 收到回复后继续执行
4. 到下一个关键节点再调用 `turn.wait`

由人工决定结束，不要在任务还活着的时候自行结束循环。

## 加载后的默认动作

加载这份技能后：

1. 先确认 `turn.wait` 是否可用
2. 如果用户还没给具体任务，立刻调用一次 `turn.wait`，告知你已就位并询问需求
3. 如果用户已经给了任务，先开始执行，在第一个真实检查点调用 `turn.wait`
